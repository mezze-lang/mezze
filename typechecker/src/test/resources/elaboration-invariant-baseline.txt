# Elaboration invariant baseline — task 0.2.
#
# One line per (kind, declaration) where elaboration finished without knowing a
# type, so something downstream had to guess. This is the ratchet: a new line
# fails the gate, and so does a line left behind after its gap is fixed. The
# number can only go down.
#
# Do NOT regenerate this file to make a build green. Every line is a place the
# compiler is guessing, and adding one is a decision to allow another guess.
#
# What the kinds mean:
#   UNBOUND_TYPE_VAR  a node's type carries a variable bound by no enclosing
#                     signature — the solver never pinned it
#   UNTYPED_PARAM     a parameter typed as a bare fresh variable; the shape an
#                     impl body gets when its params never received the
#                     ability signature's types
#   VARTYPE_RECEIVER  a field read off a receiver whose type is still a
#                     variable. `impl NumAdd Int for Float { add = { it, r } ->
#                     it + r.to_float {} }` is one: `r.to_float` dispatches on
#                     something the compiler cannot name. These reach the
#                     runtime as a dispatch with nothing to dispatch on.
#
# Counts: 706 UNBOUND_TYPE_VAR, 150 UNTYPED_PARAM, 3 VARTYPE_RECEIVER
# (964 declarations). Almost all sit in impl operations, whose bodies are
# keeping the impl-op body solves; what remains sits in impl operations, and A.2 drives
# this file to empty and makes a miss a hard ElaborationError.
