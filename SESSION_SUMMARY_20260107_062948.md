## Problem Statement

StructuredConcurrencyTest was failing with TypeChecker errors where closure variables in deeply nested lambdas (3+ levels deep) were being typed incorrectly. Specifically:

```
Type Error: Type Promise does not support required ability 'NumMul'
```

This occurred when code like `{x} -> spawn {computation = {} -> x * 2}` tried to use the closure variable `x` in an arithmetic operation. The type checker was incorrectly typing `x` as `Promise` instead of `Int`.

## Root Cause Analysis

The issue was identified as a **bidirectional type inference problem** in the TypeChecker. When inferring nested lambdas inside record literals passed as function arguments:

1. Function calls used **forward inference** for arguments instead of **bidirectional inference**
2. Record literal fields were inferred independently without propagating type information
3. Lambda parameters in nested contexts didn't receive expected types from outer context

### Example of Failing Code Pattern

```funk
let promises = items |> array::map {xs = @, f = {x} -> spawn {computation = {} -> x * 2}}
```

Where:
- `items: [Int]`
- `array::map` has type `{ xs: ['a], f: { x: 'a } -> 'b } -> ['b]`
- Parameter `x` should be typed as `Int` but was getting typed as `Promise`

## Technical Details

### Type System Architecture

The TypeChecker uses:
- **Constraint-based type inference** with unification
- **Bidirectional type inference** (inferBasicTypeWithExpected)
- **Let-polymorphism** with fresh type variable instantiation
- **Substitution accumulation** (accumulatedSubstitutions map)

### Relevant Functions

1. `inferBasicTypeWithExpected(expr, expectedType)` - Bidirectional inference
2. `inferBasicType(expr)` - Forward inference
3. `solveConstraints()` - Unification and substitution generation
4. `applySubstitutionToType(type, substitutions)` - Apply substitutions to types
5. `inferLambdaWithExpectedType(expr, expectedType)` - Lambda parameter setup

### Current Flow for Nested Lambdas

```
1. Infer function call: array::map
   - Function type: { xs: ['a], f: { x: 'a } -> 'b } -> ['b]

2. Infer arguments bidirectionally
   - Expected: { xs: ['a], f: { x: 'a } -> 'b }

3. Infer record literal { xs = @, f = {x} -> ... }
   - Field xs: infer @ with expected type ['a]
   - Field f: infer {x} -> ... with expected type { x: 'a } -> 'b

4. Infer lambda {x} -> spawn {computation = {} -> x * 2}
   - Set parameter x to type 'a (from expected param type)
   - Add x: 'a to context
   - Infer body: spawn {computation = {} -> x * 2}

5. Infer spawn call
   - Infer argument {computation = {} -> x * 2}
   - Infer nested lambda {} -> x * 2
   - Look up x in context -> gets 'a (PROBLEM: should be Int after substitution)
   - Infer x * 2 -> requires NumMul 'a

6. Type error: 'a gets unified with Promise, causing NumMul error
```
